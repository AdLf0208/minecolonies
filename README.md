# MineColonies for Horizon — slices 1, 2 and 3

A Horizon port of [MineColonies](https://github.com/ldtteam/minecolonies): **a town hall founds a
colony, its citizens take jobs that tick in the world** — a farmer, a lumberjack and a miner, each
in **its own building** — and `/minecolonies colony|citizen|job` configures it.

Delivered as **one flat SDK package**: [`minecolonies.hmod`](minecolonies.hmod) — `horizon-mod.toml`
(api `0.2`, `side = "both"`, `capabilities = ["registries"]`, `[native]` pinned to
`0a875da`/`e59da90`), `src/` (the Rust), `assets/` and `data/` (the blocks, the item and the citizen
entity type) and the licence files. Install it and place the town hall; `/minecolonies colony info`
shows the colony.

## What this port does

- **Founding.** Placing `minecolonies:blockhuttownhall` founds a colony named `<you>'s Colony`
  with you as its owner, a 64-block (4-chunk) radius, and the whole record saved with the town
  hall. Placing it where a colony would be too close (under
  `max(minColonyDistance, initialColonySize) × 16` = 128 blocks, measured horizontally), or where
  you already own a colony, is refused before the block appears. `/minecolonies colony rename`,
  `… colony radius <chunks>`, `… colony info`.
- **Citizens.** `/minecolonies citizen hire [name]` recruits a citizen into the colony;
  `/minecolonies citizen list` shows the roster.
- **Jobs.** `/minecolonies job assign <citizen> farmer|lumberjack|miner`, each stepping once per 40
  ticks on the roster's own cadence:
  - **farmer** — needs a `minecolonies:blockhutfarmer`; walks to a mature crop inside the colony,
    harvests it and leaves it replanted; the colony counts the crop.
  - **lumberjack** — needs a `minecolonies:blockhutlumberjack`; finds a tree inside the colony,
    walks to it and fells **every connected log**
    from the top down, leaving the leaves; the logs go into the colony's chest and the colony counts
    them; the stump's soil gets a sapling back **when the chest holds one**.
  - **miner** — needs a `minecolonies:blockhutminer` (the mine); sinks a **1×1 shaft** straight
    down from where it stands, one block per step, never into bedrock, water or lava, never past the
    colony, and every drop goes into the colony's chest.
  A job is **refused** while its building is not standing inside the colony, `/minecolonies job info`
  reports the building as `present` or `missing`, and **breaking the hut** takes the building with
  it.
- **Persistence.** The colony, its roster, its job counters and each citizen's job are saved with
  the world, and the jobs resume after a relaunch.

## What this port does not do

The other ~35 jobs, the builder and the building schematics, the research tree, the colony and
citizen UIs, happiness, saturation, requests, raids, permissions, colony growth from buildings and
world-gen colonies are **not implemented** — see
[`notes.md`](notes.md#gaps-stated-not-hidden) and its coverage table.
The citizen draws with its villager template's model; its own texture is generated but a renderer
for it is a later slice.

## Building and testing

The crate needs the pinned SDK, which any `cargo horizon-mod` command fetches into `.horizon/sdk/`
(git-ignored, never packed):

```sh
# the pure rules and the glue, against the pinned SDK (no game needed)
cargo test --offline --locked
cargo clippy --offline --locked --all-targets -- -D warnings
cargo fmt --check

# the one-file package, then the registry checks
cargo horizon-mod build                                   # target/horizon-mod/minecolonies.hmod
cargo horizon-mod check target/horizon-mod/minecolonies.hmod
cargo horizon-mod check --uses target/horizon-mod/minecolonies.hmod   # compiles src/
cargo horizon-mod fits target/horizon-mod/minecolonies.hmod

# the carried content is regenerated, never edited
python3 tools/assemble_content.py --check
python3 tools/gen_assets.py --check

# the in-game scenario: a launcher-built game at the pin, the prepared 26.3 resources and a ctl
eval "$(../tools/launcher-game.sh env minecolonies)"
ports/tools/build-slot.sh run --job e2e-minecolonies --port ports/minecolonies --step e2e -- \
    bash ports/minecolonies/tools/e2e.sh                 # phases A-N, PASS + EXIT:0
GAME=$CONTROL_GAME … tools/e2e.sh                        # the unmodified Nightly: fails on the ids
SELFTEST=1 … tools/e2e.sh                                # the miner's depth inverted: FAIL
```

Everything under a build slot (see `../_shared/build-slots-usage.md`), e.g.

```sh
ports/tools/build-slot.sh run --job sdk-mc --port ports/minecolonies --step check -- \
    sh -c 'cargo horizon-mod build && cargo horizon-mod check target/horizon-mod/minecolonies.hmod'
```
