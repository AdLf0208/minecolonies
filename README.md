# MineColonies for Horizon — slice 1

A Horizon port of [MineColonies](https://github.com/ldtteam/minecolonies): **a town hall founds a
colony, a citizen joins it and works the farmer's job**, and `/minecolonies colony|citizen|job`
configures it.

Delivered as **one flat SDK package**: [`minecolonies.hmod`](minecolonies.hmod) — `horizon-mod.toml`
(api `0.2`, `side = "both"`, `capabilities = ["registries"]`, `[native]` pinned to
`0b14f8a`/`e59da90`), `src/` (the Rust), `assets/` and `data/` (the blocks, the item and the citizen
entity type) and the licence files. Install it and place the town hall; `/minecolonies colony info`
shows the colony.

## What this slice does

- **Founding.** Placing `minecolonies:blockhuttownhall` founds a colony named `<you>'s Colony`
  with you as its owner, a 64-block (4-chunk) radius, and the whole record saved with the town
  hall. Placing it where a colony would be too close (under
  `max(minColonyDistance, initialColonySize) × 16` = 128 blocks, measured horizontally), or where
  you already own a colony, is refused before the block appears. `/minecolonies colony rename`,
  `… colony radius <chunks>`, `… colony info`.
- **A citizen.** `/minecolonies citizen hire [name]` recruits a citizen into the colony;
  `/minecolonies citizen list` shows the roster.
- **A job.** `/minecolonies job assign <citizen> farmer` gives a citizen the farmer's job (it needs
  a `minecolonies:blockhutfarmer` in the colony). The farmer walks to a mature crop inside the
  colony every 40 ticks, harvests it and leaves it replanted; the colony counts the crop. A citizen
  with no colony does nothing.
- **Persistence.** The colony, its roster and the harvest count are saved with the world, and the
  job resumes after a relaunch.

## What this slice does not do

The other ~40 jobs, the builder and the building schematics, the research tree, the colony and
citizen UIs, happiness, saturation, requests, raids, permissions, colony growth from buildings and
world-gen colonies are **not implemented** (see [`notes.md`](notes.md#gaps-stated-not-hidden)).
The citizen draws with its villager template's model; its own texture is generated but a renderer
for it is a later slice.

## Building and testing

The crate needs the pinned SDK, which any `cargo horizon-mod` command fetches into `.horizon/sdk/`
(git-ignored, never packed):

```sh
# the pure rules and the glue, against the pinned SDK (no game needed)
cargo test --offline --locked
cargo clippy --offline --locked --all-targets -- -D warnings
cargo fmt --check

# the one-file package, then the registry checks
cargo horizon-mod build                                   # target/horizon-mod/minecolonies.hmod
cargo horizon-mod check target/horizon-mod/minecolonies.hmod
cargo horizon-mod check --uses target/horizon-mod/minecolonies.hmod   # compiles src/
cargo horizon-mod fits target/horizon-mod/minecolonies.hmod

# the carried content is regenerated, never edited
python3 tools/assemble_content.py --check
python3 tools/gen_assets.py --check

# the in-game scenario: needs a game built at the pin, the prepared 26.3 resources and a ctl
GAME=<horizon-client at 0b14f8a> tools/e2e.sh            # --dev-mod <this directory>
CONTROL=1 GAME=… tools/e2e.sh                            # the same game with no --dev-mod
```

Everything under a build slot (see `../_shared/build-slots-usage.md`), e.g.

```sh
ports/tools/build-slot.sh run --job sdk-mc --port ports/minecolonies --step check -- \
    sh -c 'cargo horizon-mod build && cargo horizon-mod check target/horizon-mod/minecolonies.hmod'
```
